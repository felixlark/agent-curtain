# 2026-10-09 解锁恢复故障复盘

## 结论与现场

这次暴露的是恢复契约和验收方法的缺陷：显示器上线、窗口恢复和亮度恢复没有形成一个逐项验证的完整结果；部分未知状态被当成完成。此前局部修复及一次成功循环不能证明持续可靠。

现场为 macOS 27.0（26A428）、BetterDisplay 5.0.5，system-spi 后端，BetterDisplay Pro 关闭。最初安装版报告四屏上线但 `ok=false`、15 个窗口待恢复，错误包含 MenuBarAgent、Finder、Mail、Chrome、ChatGPT 等。原始窗口快照创建于 10 月 8 日 21:06；旧亮度备份已被删除，不能据此还原那次失败前的精确亮度。

## 已发现的故障与修复

| 问题 | 证据与影响 | 本次处理 |
| --- | --- | --- |
| 恢复对象范围错误 | AX 把 macOS MenuBarAgent 的四个菜单栏暴露为可移动对话框；窗口服务器会自行重排它们。另有无对应屏幕窗口的临时 AX 对话框。 | 排除系统菜单栏及无屏幕窗口依据的 AX 对话框；保留普通窗口、可移动固定尺寸窗口及有真实屏幕窗口的对话框。旧快照使用同一筛选规则，排除数单独记录。 |
| 显示参数恢复顺序错误 | 真实循环中，重新上线的竖屏、内屏先后在分辨率设置时返回 `Failed.`，随后再次解除可成功。之前在恢复原主屏和布局前校验分辨率，过渡参数触发不必要写入。 | 先恢复原主屏和布局，再等待旋转、分辨率稳定读回；自然恢复到目标时不写入，仅在有界等待后仍不匹配时进行一次写入并复核。原始错误保留具体参数与 UUID。 |
| 未知进程状态被视为消失 | 中间候选将四个窗口记作消失并删除快照，但对应四个原进程仍在运行。改用内核启动时间后，同一保存快照恢复四个窗口，消失数为零。 | 内核 PID 启动时间作为进程生命周期依据。活 PID 的应用元数据不可用或身份不一致时报错并保留记录，AX 枚举失败不能当成空窗口列表。应用元数据为何在该时点产生异常尚无完整内部追踪，不能把推断写成已证实的 macOS 根因。 |
| 部分失败反复重放整份布局 | 一项失败保留整份快照，成功窗口也反复恢复；失败日志未保留实际几何读回。 | 成功与失败独立统计，重试队列只保存失败窗口并保留原时间戳。成功和失败都记录恢复前后快照、排除数、失败对象及错误。匹配时保留原 AX 枚举 ordinal，避免过滤导致编号变化。 |
| 亮度读回不完整 | 总亮度、硬件亮度、软件亮度相互关联。旧实现验证中途读数，没有全部组件写完后的稳定读回；故障现场也缺少已删除备份的审计。 | 最后一次写入后连续三次验证总亮度与保存的组件，失败保留恢复备份；保存独立亮度审计。仍按 UUID 恢复锁屏前的值，未改成固定 100%。此次历史亮度错误的唯一触发原因因原备份缺失不能确定。 |
| 快捷键入口不一致 | 快捷键分别存在于 Karabiner、全局/局部键盘监听、保护期间的输入拦截、菜单和横幅中。 | 五处统一去掉必需的 Shift，改为 Ctrl + Option + Command + L / U；仅修改 Karabiner 的两条 curtain 规则，保留其他规则。 |

## 验证结果

安装候选：1.1.2，`/Applications/AgentCurtain.app`。Developer ID 为 `LONGBIAO CHEN (HJG65XBC25)`，运行时加固与时间戳签名；安装版和签名候选的主程序 SHA256 均为 `90d45cd93358d73d0ca81a6133246d8150de76e8afaef0233d0206f8fd685529`。

- 19 项 XCTest、36 项 Swift Testing 通过。新增回归覆盖系统/临时窗口排除、主屏恢复顺序、竖屏过渡参数和组件写入破坏总亮度的假成功。
- 窗口控制器隔离回归 4/4、状态机回归 8/8；崩溃看护隔离集成、横幅布局与生命周期检查通过。看护 fixture 仍假定恢复到 100%，已修正为保存的 0.75，并验证最终读回。
- 最终同一候选连续两轮真实 4→1→4 成功：第一轮 6 个捕获对象全部几何匹配（5 个普通窗口及 Finder 临时对话框），第二轮 4 个普通窗口全部匹配，无假消失、无失败残留。
- 每轮逐 UUID 比较保存与恢复后的显示原点、分辨率及三类亮度。专门设置 DELL 软件亮度 0.8，真实解锁后仍为 0.8；测试结束还原为测试前的 1.0。内屏保存的非默认亮度亦正确恢复。
- 官方 Computer Use 核验新版解除横幅 `⌃⌥⌘U`，恢复后的 Finder 原生窗口和文件菜单可交互；关闭本次创建的 Finder 测试窗口，现场保持正常开放。
- 最终状态：`ok=true`、`state=open`、四屏上线、`restorePending=0`、`windowRestorePending=0`。`curtain doctor` 通过。

## 仍待实体操作的项目

官方 Computer Use 以两种修饰键写法注入新快捷键，均未触发 macOS 全局热键。配置、程序监听和提示已经切换；实体键盘 L/U 尚未验证，因此不把完整 Goal 标为完成，也未据此执行远端发布。最小核验是用实体键盘按 Ctrl + Option + Command + L，再按 U；随后读取状态和恢复审计。无需重新授权或登录。

本次未宣称覆盖整夜睡眠唤醒、真实热拔插或所有应用组合；未测量物理亮度及黑屏时长。若出现新故障，应先保留新的审计与活动备份，核对具体失败对象和参数，不以 pending=0 或显示器数量代替几何及亮度验证。

## 质量流程调整

恢复成功必须有显示布局、窗口几何及亮度组件的直接读回；未知状态必须保留记录并失败；部分恢复只重试未完成对象。失败快照和逐项审计用于复盘，禁止为了使状态变绿而丢弃未知窗口。单元测试、模拟看护、真实四屏流程和实体热键分开记录；真实流程失败就回到修复，不用重新安装成功或局部截图替代验收。
